Before you start

Connect to Triton

Log in before starting a run folder.

Triton access requires an active IDSC account. The cluster login host is t2.idsc.miami.edu; use your University of Miami CaneID as the username. See the official IDSC Triton page for account access, policies, and support.

SSH login
ssh YOUR_CANEID@t2.idsc.miami.edu
Off campus?

Connect through the University of Miami VPN first if your network configuration requires it. Once logged in, confirm the host with hostname and work from your project/home location rather than a local laptop path.

Step 2 — Install Miniforge and create the environments

Use a personal POWER9 Conda installation.

Triton uses linux-ppc64le, so install the matching Miniforge distribution in your home directory. It includes the fast libmamba solver; the cluster Miniconda module uses Conda's legacy solver and can take an impractical amount of time to resolve the analysis environment.

First-time Miniforge and environment setup
curl -fsSLo "$HOME/Miniforge3-Linux-ppc64le.sh" https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-Linux-ppc64le.sh
bash "$HOME/Miniforge3-Linux-ppc64le.sh" -b -p "$HOME/miniforge3"
source "$HOME/miniforge3/etc/profile.d/conda.sh"
conda config --set solver libmamba

conda env create -f environment_triton_setup.yml
conda env create -f environment_triton_analysis.yml

module load gromacs/2025.1-gcc-13.4.0-6vq7xfo
gmx_mpi --version

conda env list
conda activate cgenff
python --version

conda activate mdanalysis
python --version
Every new login shell

Run source "$HOME/miniforge3/etc/profile.d/conda.sh", then activate the environment you need. The installation and two conda env create commands are a one-time account setup. The Triton-specific files intentionally avoid the workstation linux-64 and CUDA pins.

Step 3 — Guided configuration

Answer questions once; save the scientific choices in this folder.

The Q&A finds structures, detects PDB/mmCIF chains, lets you retain intended chains, names them, and presents numbered box options. It writes pymacs_run.json, which later commands read without repeating questions.

1

Start the Q&A

For protein–protein or protein–peptide systems, select the matching system type. Choose dodecahedron unless you have a specific reason to use another box.

python pymacs_run.py configure
2

Review saved answers

Validation confirms the input structure and required choices before PyMACS changes the folder.

python pymacs_run.py validate

Step 4 — Prepare the system

Run PyMACS Step 1 on Triton.

This creates the topology, box, solvated/ionized system, and em.tpr. It is the required checkpoint before an LSF GPU job can be submitted.

Step 1 preparation
conda activate cgenff
module load gromacs/2025.1-gcc-13.4.0-6vq7xfo
python pymacs_run.py setup

python pymacs_run.py status
Do not submit until setup succeeds.

The submit command checks for topol.top, solv_ions.gro, and em.tpr. Missing inputs stop the submission rather than sending an invalid job to the queue.

Step 5 — Submit MD, analysis, and reporting

Use the GPU for MD; free it for CPU analysis.

The Triton profile submits the 1-GPU Step 2 job plus a separate dependent CPU job. The CPU job waits for successful MD, runs memory-safe chunked Step 3A, dispatches 3B or 3C when appropriate, and generates the Step 4 figurebook.

Learn what Step 2 does
Submit and monitor
python pymacs_run.py submit --profile triton --with-analysis

# Replace JOBID with the number printed by submission
bjobs -u "$USER" -w
bpeek JOBID

tail -f mdrun.log

Automatic post-MD analysis

Chunked by default, no GPU required.

The configuration Q&A records analysis threads, chunk size, interface or ligand settings, and whether to build the figurebook. The default chunk size is 1,000 frames, so large trajectories are processed incrementally rather than loaded entirely into memory.

The dependent analysis job uses 8 CPU slots and no GPU.Choose --with-analysis to submit both jobs together.Use python pymacs_run.py submit-analysis --profile triton to run analysis separately later.

Step 6 — Resume safely

Walltime is not a failed simulation.

Triton jobs have a walltime limit. PyMACS writes GROMACS checkpoints during production; use the resume command to submit the same folder again from its latest checkpoint.

python pymacs_run.py resume --profile triton
Use python pymacs_run.py status before resubmitting.Keep all generated files in the same run folder.Use Step 3A analysis after production MD completes.
